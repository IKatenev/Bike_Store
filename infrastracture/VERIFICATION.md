## Реальный цикл воркера

В отдельном временном Git-проекте создана функция add(a, b), ошибочно возвращавшая
a - b, и существующий unit test с положительными, отрицательными и нулевыми числами.

Воркер запущен через task launch → Porch detached delegate → OpenCode serve.
Контроль status/events выполнен в первую минуту. Во время выполнения передана
корректировка через steer с просьбой включить STEER_RECEIVED в финальный ответ.
Ответ содержит этот маркер. DeepSeek исправил реализацию на a + b,
сохранил тест без изменений, выполнил его и создал журнал. Процесс завершился
успешно за 14 секунд. Sol независимо прочитал результат и журнал, повторил
python -m unittest -v (exit 0), записал acceptance.md и выполнил task accept.

Проверен OpenSpec lifecycle: new change → заполнение артефактов → strict validation
→ archive → strict validation основной спецификации. При archive обнаружен
автоматический TBD Purpose; он исправлен по реальному назначению capability,
после чего основной spec прошёл strict. В промпты добавлены конкретный Purpose
для новой capability и повторная проверка после archive.

## Практические пределы

Mailbox корректировки в быстром запуске получил abandoned /
run_ended_before_steer_terminal, несмотря на STEER_RECEIVED в ответе.
Протокол требует проверять фактический эффект отдельно от транспортного статуса.
Общая гарантия корректного steering на любых задачах из этого smoke test не следует.

Windows console encoding исправлена на UTF-8 после UnicodeEncodeError при сборе
ответа. Git Bash bin/usr/bin добавляются только окружению дочерних процессов,
чтобы Porch находил sh/bash без изменения системного PATH.

Новая отдельная сессия модели Sol не запускалась для повторения своей же
проверки: оркестрацию и приёмку выполнил текущий GPT-6.1 Sol. Версия CLI и параметр
выбора модели проверены; доступность модели в другом аккаунте не гарантируется.
Реальная авторизация DeepSeek на этой машине подтверждена запуском.

Проверки не доказывают качество любого будущего проекта, соблюдение всех правил
воркером или безопасность полного доступа. Смысловую приёмку выполняет Sol;
contract/check/report gates поддерживают проверяемую дисциплину процесса.

## Повторение offline checks

```powershell
.\infrastracture\infra.ps1 test
```

Тест создаёт изолированную копию в .runtime/, не вызывает модели и не расходует
LLM-квоту. .runtime/ исключена из Git и поставляемого архива. Doctor проверяет
версии и каталог модели; он не делает отдельный платный API-запрос.
