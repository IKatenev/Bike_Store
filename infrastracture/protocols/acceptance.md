# Приёмка работы Sol

1. Собери терминальный результат `task collect <slug> --timeout 45`. Код 124
   означает продолжающуюся работу. При ошибке исследуй результат и частичные файлы.
2. Прочитай contract.json, соответствующие требования/сценарии OpenSpec,
   реальный diff и затронутые вызовы. Сверь рабочее дерево с before-status.txt:
   не приписывай воркеру уже имевшиеся пользовательские изменения. Вне Git
   отметь отсутствие надёжной исходной базы и оцени реальные файлы непосредственно.
3. Проверь нормальные, граничные и ошибочные сценарии, существенные для изменения;
   совместимость, качество и полноту тестов. Убедись, что проверки не ослаблены.
4. Выполни `task check <slug>`: команды запускает оркестратор отдельно от воркера.
   Они исполняются в корне проекта, argv берётся из согласованного контракта.
   Анализируй результат, а не только exit code. Неисполненная обязательная проверка
   остаётся препятствием; не подделывай checks.json и не обходи gate.
5. Прочитай весь deviations.md и сопоставь каждое отклонение с доказательствами.
   Недостающий журнал — незавершённый результат. Исправления проверяй повторно
   только в затронутой области и по сохраняющимся рискам.
6. Запиши acceptance.md: критерий → файл/сценарий/проверка → результат;
   разбор журнала, внеплановые изменения, принятые ограничения и итог Sol.
   При дефекте оставь задачу непринятой и создай ограниченную корректирующую задачу.
7. Только после положительной проверки выполни `task accept <slug>` и обнови
   PROGRESS.md и OpenSpec tasks.md. Этот CLI проверяет наличие отчёта и результатов,
   но не заменяет твою смысловую оценку и не защищён от намеренного обхода.
8. Когда все задачи изменения приняты и документация актуальна, проверь
   `openspec validate <change-id> --strict`, затем архивируй через OpenSpec.
   После архивирования снова выполни `openspec validate --all --strict`.
   При создании новой capability проверь конкретный Purpose в основной spec:
   автоматический archive может оставить placeholder, который strict не принимает.
   Архивирование отдельное от task accept. Не коммить, не публикуй и не деплой
   без соответствующей авторизации пользователя.
