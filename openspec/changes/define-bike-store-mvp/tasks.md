# Tasks

План реализации `define-bike-store-mvp`, 8 октября 2026 года. Источники:
[specs](../../../docs/ai/TRACEABILITY.md), [design](design.md),
[словарь](../../../docs/THESAURUS.md) и [протокол приёмки](../../../infrastracture/protocols/acceptance.md).
Сейчас создан только план: все пункты открыты, кода и продуктовых проверок ещё нет.
Создание этого файла не запускает apply, воркера, покупку ресурсов или публикацию.

Каждый пункт — ограниченный результат для отдельной рабочей сессии. `Зависимости`
означают принятые результаты, а не просто существующие файлы; порядок внутри групп
следует указанным зависимостям. Sol проверяет diff, связанные сценарии, проверки
и журнал отклонений перед отметкой выполнения. При делегировании используется один
DeepSeek v4.1 Flash/OpenCode через toolkit; контракт содержит ID пункта, границы,
точные команды и acceptance evidence. Контракты и запуски сейчас не создаются.

Технический default для приложения — npm с отдельным корневым package-lock.json;
infrastracture сохраняет собственные зависимости. В 1.1–1.3 появятся реальные
`lint`, `typecheck`, `build`, `test:unit`, `test:integration`, `test:e2e` scripts.
Ни одна из этих команд пока не считается существующей или пройденной. Тесты
транзакций используют настоящую PostgreSQL, внешние вызовы — управляемые адаптеры;
проверки Stripe/Postmark в sandbox и облачного восстановления выделены отдельно.
Обязательные сценарии из specs распределяются по пунктам через requirement IDs;
детали граничных случаев берутся из соответствующей spec, не заменяются этой краткой разбивкой.

Данные запуска и recovery evidence в группе 13 не заменяются fixtures. До их приёмки
production-продажи не включаются. Полевые CWV без выборки остаются неизмеренными;
готовность механизма мониторинга не доказывает достижение метрик. Поведение после
MVP из CNT-03 не включается в задачи.
