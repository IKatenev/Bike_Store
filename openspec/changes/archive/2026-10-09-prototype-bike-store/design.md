# Design

## Context

Основание — команда владельца 9 октября, `docs/user-scenarios.md`, `docs/ai/UX-OPEN-QUESTIONS.md` и десять delta specs `define-bike-store-mvp`. Кода приложения нет. Цель этапа — проверяемый макет всех согласованных групп экранов, не реализация серверных инвариантов.

## Goals / Non-Goals

Показать P-01–P-13, S-01–S-10 и E-01–E-03, успешные/ошибочные ветки, desktop/mobile. Предоставить рабочие ссылки и действия на fixtures. Не выбирать production-параметры сессий, 2FA, кода получения, исправления email; не выполнять реальные продажи/письма/финансовые операции. Не отмечать 69 production-задач выполненными.

## Decisions

1. Изолированные HTML/CSS/ES modules в `prototype/`, без npm-зависимостей и изменения выбранного Next.js/Payload/PostgreSQL production-стека. Локальный HTTP server на Node стандартной библиотеке, привязан только к 127.0.0.1. Hash-маршруты для воспроизводимых ссылок. Корзина/контекст/демо-заказы сохраняются в localStorage с обработкой недоступного/повреждённого storage.
2. Модули fixtures, доменных демонстрационных переходов, витрины, служебных экранов и orchestration UI разделены. Доменные имена — из `docs/THESAURUS.md`. Исходная документация/инфраструктура не перезаписываются воркером.
3. Предлагаемая временная марка PEDAL & FIELD, en-GB/GBP. Тёплый off-white, ink, forest green, terracotta; строгая типографика, много воздуха, один выразительный hero с иллюстрацией велосипеда SVG. Редакторские подборки и компактная горизонтальная форма подбора вместо множества баннеров. На телефоне поля складываются в читабельную сетку. SVG assets локальные; это образцы композиции, не реальные фотографии ассортимента.
4. Глобальный выбор доставки/магазина доступен до checkout; в заказе сохранённое получение отделено от выбора для следующей покупки. Вся корзина из одной точки. Смена контекста сохраняет недоступные строки и предупреждает. Размер/цена/наличие фильтруются на одном SKU, счётчик показывает модели; нет таблицы → нет догадки о размере.
5. One-page guest checkout, самовывоз с оплатой в магазине. Внешняя Stripe-поверхность заменена явно обозначенным simulator без полей карты. Pending/failed/confirmed/expired/cancelled/refund показываются отдельно. Retry сохраняет исходный конец 30 минут. Reorder сохраняет и отменяет старый заказ, переносит строки и связывает новый; повтор действия не создаёт дубликаты. Эти переходы демонстрируют UX, не доказывают транзакционную/платёжную безопасность.
6. Служебный demo role switcher Manager/Network Administrator — инструмент просмотра макета, не authentication. Manager доступен ко всей сети, остаткам и контенту/подборкам; закрыты ассортимент/цены/права/настройки. S-01 показывает email/password + неизбранный second factor без утверждения TOTP или длины кода. Получение — по placeholder проверки специального кода плюс отдельная полная оплата и выдача. Не хранить реальные контакты/секреты.
7. Панель «Prototype guide» содержит ссылки всех P/S/E, сценарии и reset. Демо-управление вынесено из обычного покупательского потока. Информационные и email-тексты — примеры с явным статусом draft, без выдуманных сроков перевозчика/правовых обещаний. Оптимизация фото показана как предлагаемый upload workflow, без утверждения работающего Payload/Sharp.

## Risks / Trade-offs

Fixtures, localStorage и role switcher не обеспечивают серверные полномочия, email proof, атомарность, транзакции, Stripe или GDPR-ready хранение. В прототипе запрещены внешние запросы оплаты/email. Доступность проверяется структурой/клавиатурой и responsive review; WCAG AA/все браузеры/CWV не заявляются доказанными.

## Validation / Rollback

Node syntax и behavioural checks, strict OpenSpec и независимая браузерная проверка desktop 1440 и mobile 390: подбор, SKU, корзина, смена получения, checkout/ошибки, статусы, email proof mock, роли/контент. Папка `prototype/` автономна; reset удаляет только её storage namespace. Отчёт Sol сохраняет реальные проверки и ограничения. Нет автоматического архивирования production change.
