# Design

## Context

См. proposal.md. Автономный prototype/ использует browser ES modules, синтетический state и localStorage, Node server без dependencies. Прежние 84 проверки покрывают checkout, резервы, роли и контент. Production MVP существует только как план. Пользователь разрешил реализацию и последующие итерации; запросить повторное разрешение на код не требуется.

## Goals / Non-Goals

Goals: единая обычная магазинная композиция и работоспособные новые сценарии с сохранением прежних инвариантов. Non-Goals: production OAuth, серверные аккаунты/wishlist, реальные платежи/письма, алгоритм физической совместимости, смена стека.

## Decisions

- Один system-ui sans-serif со шкалой размеров/насыщенности, #fff/#f5f5f5, #171717, синий около #1769c2. Семантические статусы и цвета товаров отдельно. Умеренные радиусы, тонкие границы, плотные сетки. Не загружать шрифты. Избегать прежней тёплой editorial-палитры.
- Header: верхняя служебная полоса; логотип/поиск/подписанные line SVG иконки; категории. Компактный context picker рядом с навигацией, Journal в служебной полосе. Mega menu по hover/focus и click с Escape; actual fixture subcategories, не бренды. Hero 3 ручных слайда без autoplay; иллюстрации остаются локальными, меняются сцена/подпись/ссылка.
- max-width примерно 1280–1360px; каталог 240px sidebar + minmax(0,1fr) с тремя карточками. До 900px две колонки; sidebar скрыт до 600px и открывается кнопкой как drawer. Для cart до 900px итог перед полями и fixed submit; нижний отступ safe-area. Контрольные размеры 1440×900, 1024×768, 768×1024, 390×844, 360×800.
- Единая cart/checkout view с одной формой и внешними submit buttons form=id. Сохранить completeCheckout и повтор/idempotency, цену/доставку/проверки. #checkout остаётся alias к той же view, чтобы сохранить старые ссылки и reorder. Draft формы хранить при смене SKU/контекста/количества и пересчитывать доставку при изменении адреса. Пустая корзина без формы и фиксированной кнопки.
- Wishlist хранит уникальные ProductModel IDs в демонстрационном аккаунте state, не резервирует SKU. До явного подтверждения намерение хранится в UI/state отдельно. Схема localStorage мигрирует старый state добавлением безопасных defaults/фильтрацией новых полей без удаления заказов. Состояние прототипа представляет одну demo persona, не реальные аккаунты. Модалка с native dialog, focus возвратом и Escape. Google/Apple показывают явное mock continuation; ни текстовый ввод email, ни provider click сам по себе не дают доступ.
- Рекомендации: normalized lower-case name tokens и brand tokens, совпадения названия выше brand-only, затем устойчивый tie-break по исходному порядку/id; максимум 6, current/unpublished исключаются. Добавить одну синтетическую раму с названием Fieldnote Gravel Frame и SKU/balance для проверяемого примера, существующие fixtures не переименовывать. Без совпадений — bikes/parts fallback. Подпись Related products с краткой оговоркой о подборе по названию и отсутствии проверки совместимости.
- Parent обновляет плановые MVP specs/catalog/customer-accounts/tasks и docs сценариев, worker правит только prototype/** и руководство/свой журнал. Тесты новых сценариев добавляются рядом с реализацией, прежние утверждения сохраняются. Browser review обязателен для layout/интерактивности, Node assertions не подменяют его.

## Risks / Trade-offs

- Повторный render теряет draft/focus → централизованно сохранять draft до render и вернуть focus там, где нужно.
- Смешение старого checkout и нового cart создаёт дубликаты → одна форма/одна функция завершения, проверки retry/reorder.
- Две карточки на 360px → min-width:0, компактный текст/картинка и wrapping; проверить в браузере.
- Demo OAuth похож на реальный → явный label и отдельное подтверждение, без внешних запросов.
- Новые поля storage ломают старое состояние → default migration и malformed/unknown IDs tests.

## Migration Plan

Последовательный worker через toolkit, parent принимает real diff/checks/browser. Исходные пользовательские правки needed-design-changes.md сохраняются. Новый change архивируется только после приёмки; прежний архив не переписывается. Откат только собственных изменений по исходному diff без удаления пользовательских данных; storage поддерживает старые состояния. Никакого deploy.
