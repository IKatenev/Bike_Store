# Отклонения — задача bike-store-prototype

Рабочий корень: `C:/Workspace/01_Projects/Porfolio/Bike_Store`.

Журнал фиксирует неожиданные находки, доказательства, действия и разрешение.
Записи не расширяют рамки задачи.

## D-01. Общие объекты фикстур мутировались между проверками (найдено самостоятельно)

- **Ожидалось:** каждый `createSeed()` возвращает независимый набор данных.
- **Наблюдалось:** `createSeed()` возвращал модульные объекты `TARIFFS`, `REGIONS`,
  `TAX_CATEGORIES`, `SHIPPING_CLASSES` по ссылке. Тест «missing base config blocks»
  делал `delete seed.tariffs.base.bicycle`, из-за чего все последующие проверки
  получали `no_tariff` и падали.
- **Доказательство:** `node prototype/check.mjs` — 31 падение, включая
  `deliveryOrder failed ... "No delivery tariff is configured for this region."`.
- **Действие:** в `fixtures.mjs` эти четыре набора теперь возвращаются копиями
  (`.map(c => ({...c}))`, `{base:{...},extra:{...}}`).
- **Разрешение:** проверки проходят; поведение изолировано.

## D-02. `reservedQuantity` игнорировала позиции резерва (найдено самостоятельно)

- **Ожидалось:** доступное количество учитывает активные резервы; корректировка
  остатка ниже резерва отклоняется.
- **Наблюдалось:** `reservedQuantity` фильтровала `r.skuId/r.qty`, тогда как
  резервы хранят массив `items`. Итог всегда 0: доступность не уменьшалась,
  `staffAdjustStock` не находил конфликта.
- **Доказательство:** падение тестов `stock adjustment rejects a drop below
  reserved amount` и доступности при смене контекста.
- **Действие:** `reservedQuantity` суммирует `r.items` активных резервов.
- **Разрешение:** проверки защиты резервов и доступности проходят.

## D-03. `resolvePath` и проверка обхода каталога

- **Ожидалось:** сервер не отдаёт файлы вне `prototype/`.
- **Наблюдалось:** `path.normalize` для абсолютных URL «съедал» `..`, поэтому
  явного отказа не было (файл вне корня и так недостижим). Тест ожидал `null`
  и падал на `/../secret`.
- **Действие:** `resolvePath` теперь явно отклоняет любой сегмент `..` (defence in
  depth) и сохраняет проверку `startsWith(root)`.
- **Доказательство:** smoke-тест сервера — `/` 200 `text/html`, `/app.mjs` 200
  `text/javascript`, обход не отдаётся.
- **Разрешение:** проверка пути проходит.

## D-04. Правки оркестратора перед приёмкой (7 доменных)

Все исправлены и покрыты проверками; поведение из correction-01 сохранено
(внешние примеры Sol прошли, `parent-check.mjs` не изменялся).

1. **Тариф доставки.** Было `max(base+surcharge)` по классу; стало `max BASE` +
   все настроенные надбавки за количество. 2 Bicycle + 2 Oversized = 3995.
   Отсутствие base/quantity конфигурации блокирует, не даёт ноль/пропуск.
2. **Сроки Europe/London.** Было локальное время хоста и фиксированные 72 ч;
   стало явное преобразование Europe/London (DST-aware). Понедельник → четверг;
   весна 71 ч, осень 73 ч; продление — 3 календарных дня от исходного конца.
3. **Двухфазное переоформление.** `startReorder` отменяет/сохраняет старый и
   идемпотентно готовит черновик без заказа/резерва; `submitReorder` создаёт и
   связывает ровно один новый заказ. Гонка принятой оплаты → запрос отмены.
4. **Симулятор оплаты.** Сначала валидируется исход; failed/pending по
   отменённому заказу не создают возврат; самовывоз отклоняет онлайн-путь;
   повторные paid-события идемпотентны, включая dispatched/completed.
5. **Самовывоз.** `markReady` отклоняет cancelled/completed/не-confirmed;
   `recordCollectionPayment` только для самовывоза, требует полную сумму;
   `collect` требует confirmed+ready+полную оплату+проверку кода+не истёк.
6. **Гостевая сессия.** `guestOrders` возвращает только текущий заказ сессии;
   `verifiedHistory` — явно подтверждённая mock-персона; guide может выбрать
   текущий заказ; прямой доступ к чужому заказу требует mock-подтверждения.
7. **Защита остатков/возврата.** `staffAdjustStock` отклоняет падение ниже
   резерва; `restockReturn` ограничен купленным минус принятым и сохранённой
   точкой; возврат денег не выполняет restock.

## D-05. Правки оркестратора перед приёмкой (6 интеграционных)

1. **Параметры маршрутов.** `resolveView` брал `p[1]`; для `staff/order/<id>` и
   `staff/product/<id>` нужен последний сегмент. Теперь идентификатор — последний
   сегмент; S-03/S-07 открываются. Payment/result получили `canViewOrder`-guard.
2. **Guide.** Убраны мёртвые `SELECT_ORDER`-ссылки; добавлен сборщик сценариев
   (`seedDemoScenarios`) и выбор текущего заказа; ссылки используют реальные id.
   `seedDemoHistory` теперь действительно наполняет состояния. Образцы писем
   E-01–E-03 доступны без служебной роли; журнал диагностики скрыт вне staff.
3. **Ключи ошибок контактов.** `validateContact` возвращает `name/email/phone`,
   а представление ожидало `contact.*`. Ключи нормализованы в `checkout`.
   Delivery открывает явно обозначенный симулятор; pending не выглядит оплаченным.
4. **`submitReorder`.** Раньше использовал сохранённый черновик. Теперь берёт
   текущую корзину/контекст и текущие поля формы, сохраняя id и идемпотентность;
   изменения и недоступные строки показаны до согласия.
5. **`loadState`.** Добавлена минимальная проверка формы сохранённого состояния
   (`serializeState`/`deserializeState`); повреждённый JSON и неверные формы
   безопасно дают начальное состояние.
6. **Помощь/отмена.** Возврат проверяет целое количество 0..купленного и
   сохраняет причину/заметку; «Accept cancellation» реально принимает отмену,
   возврат денег только при полученной оплате; деньги и склад раздельны.

## D-06. Прочие находки интеграции (найдено самостоятельно)

- `deliveryOrder` в проверках наследовал collection-контекст — helper теперь
  явно ставит delivery (ошибка тестового helper, не домена).
- Теги сценариев приведены к camelCase (`collectionReady` и т. п.) для
  согласованности guide/проверок.
- `requestRefund` теперь отклоняет возврат без полученной оплаты
  (`nothing_to_refund`); соответствующие проверки обновлены.

## D-07. Storefront browser checkpoint (правки оркестратора)

Оркестратор независимо прошёл desktop/mobile: главная, подбор, смена цены SKU,
сохраняемая корзина, сохранение недоступных строк, гостевой самовывоз, полная
оплата и выдача по коду, отказ прямому маршруту Manager, публикация страницы и
подборки Manager. Найдены два оставшихся несоответствия и polish.

1. **CAT-05 цена «From» в контексте получения.** Было: `productCard` брал
   минимальную цену среди всех опубликованных SKU, а `filterModels`/поиск — min
   всех подходящих SKU независимо от наличия. Стало: цена «From» предпочитает
   подходящие варианты, ДОСТУПНЫЕ в выбранном контексте; при отсутствии доступных
   используется min подходящих недоступных с честной пометкой. Критерии не
   ослабляются. Сортировка — по показанной цене. Карточки главной/подборок
   используют тот же `modelPriceSummary`. Проверено: Delivery Fieldnote £1295
   (Terracotta на складе 0), York £1195, Bath £1295; после выдачи последней
   Terracotta в York — £1295 (Forest ещё доступен). Добавлены тесты.
2. **Сужение каталога теряло цену/рост.** Форма каталога не имела полей
   priceMax/heightCm, а submit в `app.mjs` не включал их ключи, поэтому после
   подбора с главной условия отбрасывались. Добавлены видимые подписанные
   контролы price/height/frame-size, сводка активных фильтров и сохранение
   ключей при Apply. Тесты подтверждают, что Apply не теряет ограничения.
3. **Служебная страница самовывоза.** После completed/cancelled всё ещё
   предлагались формы оплаты/выдачи. Теперь формы показываются только в
   применимых состояниях, иначе — читабельная причина; доменные guard-ы
   сохранены, оплата и выдача остаются раздельными.
4. **Визуальный polish (в границах прототипа).** Велосипед SVG перерисован как
   целостный (замкнутые треугольники рамы, вилка, руль, шатун/педаль);
   покупательский текст в hero/подборе вместо мета-описания; тело/контролы —
   sans-serif, заголовки — editorial serif. Draft-бейдж, метка симулятора,
   синтетические тарифы и открытые оговорки о безопасности сохранены.
