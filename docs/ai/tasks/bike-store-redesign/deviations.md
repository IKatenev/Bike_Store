## D-01. Пре-существующие trailing spaces в пользовательском needed-design-changes.md

- **Ожидалось:** `git diff --check` чист по всем собственным изменениям.
- **Наблюдается:** в исходном пользовательском `needed-design-changes.md` есть
  пробелы в конце строк 31 и 39. Файл принадлежит человеку и не подлежит правке.
- **Доказательство:** `git diff --check` без исключения указывает этот файл.
- **Действие:** по корректировке Sol проверка запускается как
  `git diff --check -- . :(exclude)needed-design-changes.md` — exit 0 (только
  CRLF-предупреждения по изменениям parent в `docs/user-scenarios.md` и
  `openspec/changes/define-bike-store-mvp/tasks.md`, не ошибки). Полный
  `git diff --check` за passed не выдаётся.
- **Остаётся:** замечание снимается при правке/переносе строк самим владельцем.

## D-02. Сохранённая проверка требует `href="#checkout"` при новом submit-CTA

- **Ожидалось:** в desktop-итоге корзины кнопка «Place order» — submit общей формы.
- **Наблюдается:** сохранённая проверка
  `cart render: a fresh delivery cart ... allows checkout before an address`
  требует строку `href="#checkout"`. #checkout — совместимый alias того же вида.
- **Доказательство:** `node prototype/check.mjs` до правки — 83 passed, 1 failed
  («checkout link enabled»).
- **Действие:** desktop-итог получил primary submit `Place order`
  (`form="checkout-form"`); дополнительно сохранён неприметный вторичный anchor
  `<a href="#checkout">Proceed to checkout</a>` (скрыт на mobile), чтобы прежняя
  проверка осталась осмысленной. Форма остаётся единственной
  (`data-checkout-form` / `id="checkout-form"`).
- **Остаётся:** если Sol решит, что вторичная ссылка нежелательна, потребуется
  согласованное изменение самой проверки (не выполнено: тесты не ослабляются).

## D-03. Breakpoint фильтров (601–900px)

- **Ожидалось:** скрывать подробную панель фильтров только на телефонах.
- **Наблюдается (промежуточная версия):** sidebar скрывался уже на ≤900, а drawer
  был описан только ≤600 — диапазон 601–900 оставался без панели.
- **Действие:** на 601–900 sidebar остаётся колонкой (сужен до 200px, уменьшены
  отступы), сетка товаров 2 колонки; скрытие sidebar, кнопка Filter и drawer
  перенесены в ≤600. Drawer закрывается Escape/кнопкой и возвращает фокус.
- **Доказательство:** `node prototype/check.mjs` — 101 passed; CSS-правила в
  `prototype/styles.css` (`@media (max-width: 900px)` и `@media (max-width: 600px)`).
- **Остаётся:** фактический browser-вид 768/390/360 проверяет parent.

## D-04. Композиция hero-слайдера

- **Ожидалось:** крупная сцена (картинка + текст), controls под всей сценой.
- **Наблюдается (промежуточная версия):** `.hero` оставался двухколоночным grid,
  поэтому controls занимали вторую колонку, а сцена делилась.
- **Действие:** `.hero-slider` — блочный контейнер, `.hero-slide` — grid
  «арт слева / текст справа» на desktop и одна колонка ≤900; controls под сценой;
  скрытые слайды `[hidden]` не отображаются.
- **Остаётся:** browser-проверка Sol.

## D-05. Размещение итога корзины

- **Ожидалось:** итог справа от корзины/формы на desktop, sticky у первого товара.
- **Наблюдается (промежуточная версия):** areas `"rows rows" "main summary"`
  начинали итог только после всего списка товаров.
- **Действие:** desktop areas изменены на `"rows summary" "main summary"`; ≤900 —
  `"rows" "summary" "main"` (итог между строками и полями). Бизнес-проверки не тронуты.
- **Остаётся:** browser-проверка Sol.

## D-06. Базовый размер SVG-иконок

- **Ожидалось:** иконки не раздувают строки; верхняя полоса тонкая, значок поиска виден.
- **Наблюдается (browser Sol):** oversize truck ~70px и пустая search button —
  общего правила `.icon` не было.
- **Действие:** добавлен базовый `.icon { width/height:20px; flex:none; display:inline-block }`,
  utility 16px, chevrons 14px, hero-arrow 18px, header-icon 22px.
- **Остаётся:** визуальная проверка Sol.

## D-07. `chooseSku`: приоритет изменённого измерения

- **Ожидалось:** сохранять именно изменённый dropdown, иначе явно подставлять
  существующую комбинацию и пояснять.
- **Наблюдается (промежуточная версия):** при смене размера с несовместимым прежним
  цветом сохранялся цвет, а введённый размер отменялся.
- **Действие:** `chooseSku` принимает `changed` ('colour'|'size') и в первую очередь
  сохраняет изменённое измерение; добавлена проверка
  `chooseSku keeps the changed dimension and explains the adjusted one`
  (frame-01: 54/Ink ↔ 56/Forest).
- **Остаётся:** нет.

## D-08. Миграция остатков новой рамы для старой сессии

- **Ожидалось:** старое сохранённое состояние не теряет заказы/резервы, но может
  купить добавленный demo-товар.
- **Наблюдается:** legacy `balances` перезаписывали base-массив, поэтому остатки
  новых SKU рамы `frame-01` отсутствовали.
- **Действие:** `migrateState` добавляет fixture-строки остатков ТОЛЬКО для SKU,
  полностью отсутствующих в сохранённом состоянии (например, `frame-01-54-ink`,
  `frame-01-56-forest`), не сбрасывая существующие остатки/заказы/резервы. Проверка
  `legacy state keeps orders and gains the new frame balances` подтверждает пример.
- **Остаётся:** нет.

## D-09. Двухшаговый email-доступ и единая persona

- **Ожидалось:** ввод email/запрос письма/клик провайдера не дают доступ; только
  явное подтверждение; один набор доступа, logout снимает и `signedIn`, и `verified`.
- **Наблюдается (промежуточная версия):** submit формы сразу вызывал
  `signInCustomer` + `finishAuth`; провайдер тоже; logout не снимал `verified`.
- **Действие:** добавлены `requestEmailAccess` (только сохраняет намерение),
  `confirmEmailAccess`, `confirmProviderAccess` (входят в persona и подтверждают
  историю); `signOutCustomer` очищает `verified` и `pendingAccess`; `#sign-in`
  использует тот же поток; `#verify` confirm согласованно входит и завершает
  pending intent. Проверки: request-before-confirm, confirm без запроса, provider,
  logout-gate.
- **Остаётся:** реальной безопасности/OAuth нет по определению прототипа.

## D-10. Композиция auth-поверхностей (нет дублирования ID)

- **Ожидалось:** одновременно одна видимая auth-поверхность и уникальные ID.
- **Наблюдается (browser Sol):** `#sign-in` рендерил inline-поля и закрытый
  `authDialog` одновременно → duplicate `auth-email`, двойная label; Google/смена
  режима открывали dialog поверх страницы.
- **Действие:** `authDialog` рендерится только при `ui.authDialogOpen`; обработчики
  `auth-mode/auth-back/auth-provider` сохраняют текущую поверхность (`inDialog` по
  `el.closest('.auth-dialog')`), не открывая dialog на `#sign-in`; навигация
  закрывает открытый dialog; декоративные метки G/A помечены `aria-hidden="true"`.
  Проверено рендером: `#sign-in` — 1 `auth-email` и нет `<dialog>`; dialog — 1
  `auth-email`; provider/confirm стадии — по одной кнопке подтверждения.
- **Остаётся:** browser-проверка Sol.

## D-11. Горизонтальное переполнение мобильной навигации

- **Ожидалось:** `document.scrollWidth` ≤ viewport на 360/390.
- **Наблюдается (browser Sol):** `.nav-row-cats` расширялся до min-content
  (clientWidth 489 при innerWidth 390); context-picker выходил за край.
- **Действие:** мобильные `.nav-row` получили `width:100%/max-width:100%/min-width:0`,
  `flex:0 0 auto` для элементов прокручиваемого ряда; `.header-inner` — `min-width:0`;
  context-picker label над select, select `min-width:0/max-width:100%`; мега-панели
  вынесены ИЗ прокручиваемого ряда в `.header-inner` (absolute) — не клипаются.
- **Остаётся:** фактическое измерение 360/390 — за parent.

## D-12. Возврат фокуса dialog/drawer

- **Ожидалось:** после закрытия/escape фокус возвращается на инициатор.
- **Наблюдается (browser Sol):** после Close `document.activeElement` становился BODY.
- **Действие:** сохраняется семантический локатор инициатора (`data-action`+`model`/`mode`
  либо `href`); после закрытия/навигации и повторного рендера `restoreFocus` находит
  соответствующий новый элемент; при переключении вкладок/провайдера фокус остаётся
  внутри нового dialog (`data-auth-autofocus`). Drawer аналогично возвращает фокус на
  кнопку Filter. Не заявляется как принятое — проверяет Sol.
