## D-01. Checkout не начинал оплату доставки (дефект, найден Sol при браузерной приёмке)

- **Ожидалось:** успешное оформление доставки (новой или переоформления) начинает
  оплату ровно один раз и открывает `#payment/<newid>`; заказ pending с действующим
  исходным 30-минутным резервом. Самовывоз остаётся confirmed/unpaid на `#result`.
- **Наблюдалось:** обработчик submit в `prototype/app.mjs` вызывал
  `createOrder`/`submitReorder` и сразу переходил на `#result/<id>`, не вызывая
  `beginPayment`. Резерв не создавался. `canReorder` в `domain.mjs` считал
  `!reservationActive(...)` (в том числе отсутствие резерва) признаком истечения,
  поэтому свежесозданный заказ показывался как «резерв истёк».
- **Тестовый пробел:** доменные проверки вызывали `beginPayment` вручную, поэтому
  отсутствие вызова `beginPayment` в реальном UI-пути оформления не выявлялось.
- **Доказательство:** браузерная приёмка Sol — свежее переоформление доставки
  `ord-0010` без резерва отобразилось как истёкшее.
- **Действие:** в `domain.mjs` выделен узкий общий чистый `completeCheckout(seed,
  state, options)`: для доставки он вызывает `beginPayment` ровно один раз
  (идемпотентно) и возвращает `next:'payment'`, для самовывоза — `next:'result'`.
  `app.mjs` использует этот helper. `canReorder` ужесточён: требует фактически
  существовавший и истёкший/освобождённый резерв доставки; незапущенная оплата не
  считается истёкшей.

## D-02. Тексты результата заказа были неточными

- **Ожидалось:** самовывоз по фактическому состоянию; доставка dispatched/delivered
  не обещает будущую отправку.
- **Наблюдалось:** ветка `isCollection` шла первой и всегда писала «confirmed и
  unpaid», даже для completed/cancelled; ветка `paid` обещала будущую отправку.
- **Действие:** переписан `nextStep` в `storefront.mjs result()`; в `order()`
  «Reservation expired» только для реально истёкшего резерва, для незапущенной
  оплаты — «payment has not started».
- **Доказательство:** 11/11 parent-проверок (включая новые Sol) проходят.

## D-03. «Decline this order» — якорь без href

- **Наблюдалось:** в `result()` действие отмены — `<a class="btn btn-ghost"
  data-action="cancel-order">` без `href`.
- **Действие:** заменено на `<button type="button">`; смежные действия уже были
  кнопками/ссылками с `href`.

## D-04. Mobile: таблица распирала страницу (первая попытка не сработала)

- **Наблюдалось (DOM Sol, 360 px):** `#staff/order/ord-0006`/`ord-0008` — page
  `scrollWidth` 385 > `innerWidth` 360.
- **Первая попытка (неудачная):** `max-width:100%` на mobile `.data-table`. Sol на
  свежем CSS: tableWidth 259 / tableScroll 344, но page scrollWidth всё ещё 385;
  `max-width` не ограничивает table-бокс ниже min-content.
- **Действие (корректное):** таблица «Items» в `staff.mjs staffOrder()` обёрнута в
  `<div class="table-scroll">`; в `styles.css` добавлены
  `.table-scroll { max-width:100%; min-width:0; overflow-x:auto; }` и
  `.table-scroll .data-table { display:table; width:100%; max-width:none;
  overflow:visible; }`. Таблица «Items» в гостевом `storefront.mjs order()`
  обёрнута так же. Семантика/заголовки сохранены, глобального скрытия overflow нет.
- **Доказательство (Node):** тесты «Items tables use a block scroll wrapper» и
  «styles.css keeps the scroll-wrapper override».
- **Уточнение причины (Sol, повторный CUA):** обёртка подтверждена, но page
  scrollWidth всё ещё 385 из-за неразрывного токена в абзаце Email diagnostics
  (см. D-09).
- **Оставшееся:** измерение page scrollWidth 360/390/768/1440 — на стороне Sol.

## D-05. S-04: метки возврата не связаны с полями

- **Наблюдалось:** `#staff/returns` — `<label>Line</label><select name="skuId">` и
  `<label>Quantity to accept</label><input name="qty">` без for/id/обёртки.
- **Действие:** в `staffReturns()` добавлены `for`/`id` `ret-line-<orderId>` и
  `ret-qty-<orderId>`; имена и обработчики сохранены.

## D-07. Корзина блокировала свежую доставку без адреса (дефект, найден Sol CUA)

- **Наблюдалось:** свежий `#product/gravel-01` → Add to cart → `#cart`:
  «Delivery cannot be priced for this context», Delivery «Not configured»,
  «Proceed to checkout» disabled. Без адреса `computeShipping` возвращал
  `no_address`, и корзина блокировала покупку.
- **Тестовый пробел:** Node-помощники подставляли `ADDRESS`; реальный UI-гейт
  корзины без адреса не проверялся.
- **Действие:** в `storefront.mjs cart()` «ожидание адреса» (`no_address`)
  отделено от реальной проблемы доставки (`excluded`/`no_tariff`). Блокировка —
  только для реальной проблемы и недоступной строки. Метка «Calculated at
  checkout», итог «Total before delivery (VAT included)» (сумма товаров; нулевая
  доставка не выдаётся за настроенную). Валидация по адресу при отправке формы не
  ослаблена; адрес/регион по умолчанию не выдумывается.
- **Доказательство (Node):** тесты «cart render: a fresh delivery cart…» и
  «cart render: a retained unavailable row…».

## D-08. Неудачный первый фикс таблицы зафиксирован

Первая правка (только `max-width:100%`) не устранила page overflow; замена —
обёртка `.table-scroll` (см. D-04).

## D-09. Остаточный page overflow — неразрывный токен диагностики

- **Наблюдалось (Sol, повторный CUA):** обёртка корректна, но page scrollWidth 385
  на `#staff/order/ord-0006`/`ord-0008`; неразрывный токен
  `placeholder/deadline/extension/dispatch/delivery/refund` в абзаце Email
  diagnostics выходит за панель (прежний bounding-box фильтр пропустил текстовое
  переполнение). 
- **Действие:** в `staff.mjs staffOrder()` копия переписана на обычное предложение
  «E samples created vs confirmed; code placeholder, deadline, extension, dispatch,
  delivery and refund are kept truthful.» Обёртка таблицы сохранена; широких
  правок нет.
- **Доказательство (Node):** тест «staff order diagnostics copy has no unbreakable
  separator token».
- **Оставшееся:** измерение page width — на стороне Sol.
