# Прототип Bike Store (PEDAL & FIELD)

Статус: **черновик для просмотра, визуальная итерация 10 октября**. Это изолированный
интерактивный макет согласованных путей J-01–J-12 и экранов P-01–P-13 / S-01–S-10 /
E-01–E-03. Он не является production-реализацией: 75 задач активного change
`define-bike-store-mvp` остаются открытыми, визуальные и технические решения —
предложения на согласование. Итерация переработки (PRO-07–PRO-12) заменила прежнее
тёплое editorial-оформление нейтральным магазинным, добавила wishlist, вход без
пароля, рекомендации по названию и общее оформление внутри корзины. Уточнение
главной (PRO-08/PRO-13) сделало hero 70/30 с двумя брендовыми промо справа и
секцией трёх последних статей перед footer.

## Что это и чего это не делает

- Только локальная витрина и служебные макеты на синтетических данных.
- Нет production-бэкенда, аутентификации, Stripe, Postmark, CMS, Sharp,
  облачных ресурсов, реальных продаж, писем, остатков или оплат.
- Нет внешних сетевых запросов: сервер отдаёт только локальные файлы.
- Выбранный production-стек Next.js/Payload/PostgreSQL и требования MVP
  сохраняются. Ход работы и приёмка прототипа записаны отдельно в docs/ai и OpenSpec.

## Запуск

Требуется только Node.js (проверено на v26.2.0). Установка зависимостей не нужна.

```
node prototype/serve.mjs
```

Откройте <http://127.0.0.1:4173/>. Сервер слушает только loopback
`127.0.0.1`; порт по умолчанию `4173`, переопределяется переменной `PORT`:

```
$env:PORT=5000; node prototype/serve.mjs
```

Остановка — `Ctrl+C`.

`check.mjs` содержит 127 проверок: тариф доставки, календарные сроки
Europe/London с переходом на летнее время, двухфазное переоформление,
честность состояний оплаты/получения/возврата, роли и защита прямых маршрутов,
защита резервов, возврат товара, цена «From» по доступным в контексте вариантам,
сохранение фильтров каталога, состояния служебного самовывоза, сохранение
localStorage, защита путей сервера, а также интеграция оформления и корзины:
общий `completeCheckout` начинает оплату доставки ровно один раз со свежим сроком,
самовывоз остаётся confirmed/unpaid, повторная подача переоформления переиспользует
связь/резерв, честные тексты результата для незапущенной/истёкшей оплаты и
завершённого/отменённого самовывоза. Свежая доставка в корзине без адреса
разрешает оформление с честной пометкой «Calculated at checkout» (без выдуманной
бесплатной доставки); недоступная строка по-прежнему блокирует всю корзину.
Таблицы позиций заказа в служебном и гостевом представлении обёрнуты в
`.table-scroll` (обычный блочный контейнер с горизонтальной прокруткой), а
диагностический текст заказа переписан без неразрывного токена
(«code placeholder, deadline, extension, dispatch, delivery and refund»).

Итерация переработки добавила проверки: синтетическая рама `frame-01`
(Fieldnote Gravel Frame) опубликована и имеет остаток; рекомендации ранжируют по
совпадающим словам названия, исключают текущую/неопубликованную модель и имеют
fallback на bikes/parts; `chooseSku` сохраняет изменённое измерение (цвет/размер)
и явно сообщает о подстановке; wishlist требует входа, хранит уникальные id и
удаляется; запрос email сам по себе не даёт доступ — только явное подтверждение;
подтверждение провайдера входит в demo-аккаунт и подтверждает историю; выход
снимает и `signedIn`, и флаг истории; view wishlist/account отражают gate; общий
auth-поток без пароля переключает режимы; страница товара содержит выпадающие
списки, переход в корзину, wishlist и рекомендации; главная содержит ручной
слайдер из трёх слайдов; фильтр по типу работает и для запчастей; корзина и
оформление — одна форма без submit при пустой корзине; миграция старого состояния
сохраняет заказы и добавляет новые остатки рамы; повреждённый wishlist безопасно
фильтруется. Дополнительные проверки перехода контекста и checkout gate покрывают смену магазина/способа получения, восстановление тарифа доставки и сохранение блокировки недоступных строк.

Уточнение главной добавило проверки: hero содержит по одной ссылке на весь слайд,
одну CTA-span внутри ссылки (без вложенных ссылок/кнопок), заголовок-`h1`, две
равные брендовые промокарточки Northgate/Larkhill и отсутствие лишней All products;
секция показывает три последние опубликованные статьи по убыванию `publishedAt`
со стабильным tie по slug, draft исключён, при нуле скрывается, при нехватке
показывает доступные без дублей; preview ограничен четырьмя строками body, дата
форматируется en-GB; legacy-миграция добавляет только отсутствующие статьи и
заполняет отсутствующие metadata, не перезаписывая отредактированные title/body/
published и сохраняя заказы, корзину и wishlist.

Итерация товара и каталога (PRO-13–PRO-18) добавила проверки: отзывы хранятся на
уровне модели (шесть demo-отзывов на `gravel-01`), агрегируются по всем отзывам, а
не по текущей странице; пагинация по пять на страницу; отправка проверяет вход,
целый рейтинг 1–5 и непустой заголовок, описание необязательно; миграция
отфильтровывает повреждённые сохранённые отзывы (рейтинг/заголовок/дата) до
агрегации и сохраняет корректные пользовательские отзывы, не дублируя demo-набор;
checkbox-фильтры объединяются OR внутри группы и AND между группами, один SKU
по-прежнему должен удовлетворять всему набору, а одиночная legacy-ссылка ведёт
себя как список из одного значения; главная использует четырёхколоночную сетку
товаров, а default `featured` содержит четыре существующие опубликованные модели,
при этом `sale` остаётся честным фактически уценённым списком без дозаполнения;
галерея отдаёт разные локальные виды (два–три), одиночный вид без листания; карточки
каталога имеют сердце поверх изображения отдельно от ссылки товара; русские тексты
success-popup дословны.

## Как пройти основные сценарии

1. **Подбор и SKU.** На `#home` задайте цену/тип/рост/колёса/бренд — счётчик
   считает модели (не SKU). Откройте модель, переключите цвет/размер: меняются
   иллюстрация, цена и наличие. Нет таблицы ростовки — размер не угадывается.
2. **Корзина и оформление.** В `#cart` меняйте количество кнопками и вручную
   (только целое положительное). Смена контекста «For your next purchase» в
   шапке сохраняет недоступные строки и блокирует оформление всей корзины.
   В `#checkout` заполните имя/email/телефон, выберите доставку (адрес) или
   самовывоз (магазин). Ошибки показаны рядом с полями.
3. **Оплата и результат.** Доставка создаёт pending-заказ и открывает явно
   обозначенный симулятор (без полей карты). «Банк отклонил» → повтор в пределах
   исходных 30 минут (срок не продлевается). После истечения — «Оформить заново»:
   старый заказ отменяется и сохраняется, новый связывается со старым.
   Возврат на сайт сам не подтверждает оплату.
4. **Самовывоз.** Заказ сразу confirmed и unpaid. Сотрудник: готовность →
   продление один раз до истечения (до 3 календарных дней) → фиксация полной
   оплаты → выдача по демонстрационной проверке кода. Оплата и выдача — разные шаги.
5. **Email и история.** `#sign-in` запрашивает письмо (нейтрально). `#verify`
   требует явного нажатия; GET сам доступ не даёт. `#orders` показывает только
   текущий заказ сессии; история появляется после mock-подтверждения.
6. **Помощь и возврат.** `#help/<orderId>`: отказ/запрос отмены/продление/
   возврат/проблема доставки. Возврат товара и денежный возврат — раздельно;
   pending refund никогда не назван возвращёнными деньгами.
7. **Служебные роли.** `#staff/sign-in` — демонстрационный переключатель
   Manager/Network Administrator (не аутентификация). Manager видит заказы сети,
   остатки, контент; прямые маршруты ассортимента/точек/аккаунтов запрещены.
8. **Контент.** `#staff/content`: правка/публикация информационных страниц и
   журнала, выбор и порядок опубликованных товаров в подборке главной. Пустая
   подборка скрыта; цены и ассортимент недоступны Manager.
9. **Витрина итерации.** Главная: ручной hero-слайдер из трёх сцен (без
   автопрокрутки), где основной блок занимает около 70% desktop, а справа две
   равные брендовые промокарточки Northgate/Larkhill 30%; каждый слайд — одна
   ссылка на всю площадь с заголовком-`h1` и единственной CTA-span (controls
   вынесены отдельно), затем перед footer идут три последние опубликованные
   статьи с локальной картинкой, датой, заголовком и четырьмя строками body.
   Подкатегории в мега-меню, центральный поиск. Каталог: одна
   левая панель фильтров, 3 колонки desktop и 2 на небольших экранах; на телефонах
   кнопка Filter открывает drawer (Escape/close возвращают фокус). Фильтры — группы
   checkbox с счётчиками моделей и Show more для длинных групп; значения
   объединяются OR внутри группы и AND между группами, одиночные legacy-ссылки
   сохранены. Карточка товара:
   выпадающие цвет/размер (изменённое измерение сохраняется, подстановка поясняется),
   Add to cart, Go to cart, Wishlist и рекомендации по названию. Гость по Wishlist
   получает окно входа/создания; только явное подтверждение сохраняет модель один
   раз и возвращает на товар. `#wishlist` и `#account` видны лишь вошедшему; выход
   скрывает их и историю. Карточка товара теперь: галерея слева с листанием и
   увеличением (для одного изображения только увеличение, без листания),
   справа — бренд/название, звёзды и «(средний) - N Ratings» всей модели,
   цвет/размер одной строкой, цена/наличие, Add to cart (одна штука) и Go to cart;
   description и quantity в верхней карточке отсутствуют. Ниже — вкладки Description
   (описание, features, размеры), Specifications, Reviews (средний балл всех
   отзывов, Leave a review под ним, пять отзывов на страницу с numbered pagination)
   и Manufacturer (короткий demo-профиль бренда). Отзыв пишет только вошедший
   покупатель, покупка не требуется; невалидная форма не закрывается и сохраняет
   черновик. Главная: четыре товара в ряду desktop, блог — три с изображением 2:1.
   Сердце каталога — поверх изображения справа сверху, отдельным контролем от
   ссылки товара; после реального сохранения открывается русский popup
   «Товар добавлен в избранное» с кнопками «перейти в избранное» и
   «продолжить покупки».
10. **Общая корзина и оформление.** `#cart` и `#checkout` — один вид: крупные
   строки товаров, контакты/получение под ними, итог справа desktop и между
   строками и полями на маленьких экранах, закреплённая снизу кнопка Place order
   (почти на всю ширину). Черновик формы сохраняется при смене количества/контекста,
   доставка пересчитывается по адресу; пустая корзина не имеет submit.

## Демонстрационные данные и состояния

- Бренд PEDAL & FIELD, en-GB/GBP. Палитра: белый/off-white `#ffffff`/`#f5f5f5`,
  почти чёрный ink `#171717` и единственный синий акцент `#1769c2`. Один системный
  sans-serif без засечек, без пастельного editorial-оформления; цвета товаров и
  статусов сохранены отдельно.
- 8 моделей велосипедов/запчастей (включая синтетическую раму `frame-01`
  Fieldnote Gravel Frame), запчасти/аксессуары/экипировка; несколько моделей
  с самостоятельно оценёнными/окрашенными/размерными SKU; склад и два магазина;
  отсутствующая ростовка и перекрывающиеся диапазоны; уценённый и магазинный SKU.
- Демонстрационная persona аккаунта: email без пароля, Google/Apple — только
  имитация; wishlist хранит уникальные id моделей и виден лишь вошедшему.
- Сборщик сценариев в `#guide` создаёт заказы во всех состояниях: pending,
  failed, expired, cancelled+refund pending, collection preparing/ready/completed,
  dispatched, delivered. Ссылки используют реальные id.
- Состояние хранится в localStorage под ключом `bike-store-prototype`.
  Повреждённый или недоступный storage безопасно приводит к начальному
  состоянию. Reset очищает только этот ключ.

## Ограничения и открытые предложения

- Все изображения — локальные SVG-иллюстрации (не фотографии ассортимента),
  без эмодзи и внешних ресурсов. Отзывов и рейтингов нет.
- Вход в аккаунт — демонстрационный: email без пароля, Google/Apple только
  помечены как mock и не выполняют внешних запросов. Запрос email или клик по
  провайдеру сами по себе не дают доступ; лишь явное подтверждение входит в
  единственную demo persona. Реальной безопасности/OAuth/писем нет.
- Рекомендации «Related products» подбираются только по близости названий
  (нормализованные слова, tie-break по бренду) и не проверяют совместимость;
  при отсутствии совпадений используется обычный ассортимент bikes/parts.
- Wishlist хранит id моделей одной demo persona (не SKU и не резерв); старое
  состояние localStorage мигрирует безопасно: заказы/резервы сохраняются, а
  отсутствующие остатки новых demo-SKU (например, рамы `frame-01`) добавляются.
- Тарифы доставки и регионы — синтетические демо-значения; реальные правила и
  исключения — данные запуска (UX-L-01), не догадки.
- Открытые (не выбранные) параметры показаны как placeholders: механизм и срок
  гостевой сессии (UX-01), тип второго фактора (UX-05), формат кода получения
  (UX-06), исправление email и перепривязка доступа (UX-07), детали оптимизации
  фото (J-10/QUA-03). Никаких заявлений о реальной безопасности нет.
- Загрузка фото — иллюстративный workflow; работающий Payload/Sharp не заявлен.
- S-08/S-09 показывают точки, тарифы, сотрудников и границы прав на fixtures;
  полноценное редактирование настроек и аккаунтов в этих макетах не подключено.
- Соответствие WCAG 2.2 AA и Core Web Vitals не доказано: выполнены только
  структурные/native-контролы, видимый фокус, lang=en-GB и отсутствие
  переполнения страницы на проверенных основных экранах. Страницы заказов
  отдельно повторно измерены на 360/390/768/1440; широкая таблица имеет свою прокрутку.
